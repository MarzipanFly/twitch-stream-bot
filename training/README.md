# ApelsinBot — игровой интеллект и общение с чатом

## Что уже внедрено

- **102 тематические записи** в `knowledge/facts.tsv` по ключевым играм канала и популярным жанрам. Каждая запись включает название, псевдонимы, короткие сведения/оговорки по версиям и ссылку на источник.
- **Разделение игр по категориям** в `ai_game_scope.c`: FC/FIFA, ETS2, Phasmophobia, Minecraft/Create, World of Tanks, War Thunder, VALORANT, CS2, League of Legends, Rocket League, Factorio, Satisfactory, Stardew Valley, Dead by Daylight.
- **Локальный поиск знаний (RAG)**: сначала точные ключевые слова, затем при наличии игрового контекста — семантический поиск `qwen3-embedding:0.6b`. База расширена до 128 возможных записей, эмбеддинги обрабатываются порциями по 12.
- **Контекст тестового чата**: до четырёх предыдущих вопросов и ответов хранятся только в RAM процесса. Кнопка «Начать новый диалог» удаляет этот контекст. Тест не отправляет сообщения в Twitch и не пишет их в постоянную память зрителей.
- **84 оригинальных примера диалогов** в `training/dialogues.jsonl` (74 коротких и 10 многоходовых). Это материал для будущей supervised fine-tuning, **не** автоматически подгружаемый системный промпт.
- **21 сценарий оценки качества** в `training/evaluation.jsonl`.

**Важно:** новые знания — это локальная база, а не изменение весов языковой модели. Сейчас Ollama использует уже установленную модель `apelsinbot:latest`. Само дообучение весов (LoRA/QLoRA) на компьютере пользователя не проводилось. Примеры из JSONL специально **не** вставляются как готовые ответы в промпт: ранее это приводило к повторяющимся шаблонам.

## Быстрая проверка без Twitch-эфира

Открой PowerShell в корне проекта, запусти ApelsinBot и Ollama, затем:

```powershell
py -3 tests/validate_ai_data.py
py -3 tests/eval_dashboard_ai.py --list --limit 10
py -3 tests/eval_dashboard_ai.py --limit 10 --output ai_eval_report.json
```

Для полного прогона:

```powershell
py -3 tests/eval_dashboard_ai.py --limit 0 --timeout 90 --output ai_eval_full.json
```

Скрипт обращается **только к** `http://127.0.0.1:8765` и вызывает локальную функцию `ai_test`. Ни один тестовый ответ не посылается в Twitch. Он записывает ответы в указанный JSON-файл, который остаётся локально. Не загружай этот файл в публичный репозиторий, если в собственных тестах были личные сведения.

### Критерии проверки

Проверь вручную: понятен ли смысл вопроса; учитывает ли бот переданные факты (счёт 0:2, время, игру); не переносит ли он Minecraft в футбольный разговор; отвечает ли конкретно на просьбу о совете; не изобретает ли текущий счёт/события; держит ли предыдущую реплику в памяти; избегает ли оскорблений и выдачи секретов.

Автоматические флаги `review_flags` — **подсказки для ручного просмотра**, а не объективная оценка правильности генерации. Одинаковые фактические ответы иногда допустимы, а красивый ответ не гарантирует правильность фактов.

## Обновление знаний

Добавляй новую строку в `knowledge/facts.tsv` в формате:

```text
Название темы<TAB>ключ1,ключ2,синоним<TAB>Проверенные сведения с оговорками по версиям.<TAB>https://source.example/page
```

Используй реальные символы табуляции вместо `<TAB>`. Одна строка должна быть короче 1600 **байт** UTF-8. Не добавляй источники, которых не проверял, или непроверенные точные характеристики. При добавлении категории дополняй `ai_game_scope.h/.c` и тесты. Сейчас число документов должно быть не более `SEM_MAX_DOCS` (128). Программа читает копию `knowledge/facts.tsv`, находящуюся возле запущенного `twitchbot.exe` или в рабочей директории; после обновления в GitHub пересобери проект и перезапусти процесс.

## Будущее реальное дообучение весов

1. Собрать и очистить **добровольно предоставленные** примеры диалогов и игрового QA, удалить личные сведения и секреты. Не собирать настоящую историю чата зрителей без их согласия.
2. Разделить корпус на обучение и контроль (не включать контрольные сообщения в тренировку), вручную проверить факты, не приучать модель повторять заготовки.
3. Подобрать совместимый **исходный базовый чекпойнт** для `apelsinbot` и окружение с GPU, выполнить отдельное LoRA/QLoRA SFT в поддерживаемом фреймворке. Это не команда `ollama create`: Ollama сама по себе не обучает веса.
4. Сравнить с текущей моделью на одних и тех же тестах, проверить на новых играх и неоднозначных сообщениях. Только затем объединять адаптер, экспортировать совместимый формат и создавать новую версию модели в Ollama.
5. Оставить старую модель для отката. Подключить новую через `model=` в локальной конфигурации только после проверки.

Этот репозиторий на данном этапе содержит **данные и инфраструктуру проверки**, а не готовый GPU-пайплайн обучения или уже обученный LoRA-адаптер. Рекомендации и мета-стратегии меняются с патчами: для актуальных точных деталей необходима проверка.
