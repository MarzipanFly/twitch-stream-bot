# Twitch Stream Bot

Консольный Twitch-бот на **C** для Windows. Проект собирается через **qmake / Qt Creator** и использует Twitch Helix API, EventSub WebSocket и Telegram Bot API.

**Состояние проекта:** звуковые эффекты OBS (0.8.0) реализованы; в ветке `main` ведётся разработка музыкального модуля 0.9. Музыкальные заявки, воспроизведение, пропуск и текстовый оверлей уже проверялись на Windows с OBS.

Бот авторизуется в Twitch, следит за стримом, уведомляет Telegram, обрабатывает Twitch-чат через EventSub, ведёт локальные профили зрителей, экономику апельсинов, мини-игры и случайные дропы. Звания вычисляются по текущему балансу.

## Возможности

- Twitch Device Code OAuth;
- безопасное хранение `access_token` и `refresh_token` через Windows DPAPI;
- автоматическая загрузка, проверка и обновление OAuth-сессии;
- получение данных Twitch-пользователя через Helix;
- мониторинг стрима через `GET /helix/streams`;
- обнаружение переходов `OFFLINE -> ONLINE` и `ONLINE -> OFFLINE`;
- Telegram-уведомление при начале стрима;
- отправка сообщений в Twitch-чат через Helix;
- получение сообщений Twitch-чата через EventSub WebSocket;
- постоянная обработка команд в обычном режиме запуска;
- информационные команды со ссылками на Telegram и Discord;
- персональные кулдауны для каждого зрителя и каждой команды;
- повторное подключение EventSub после потери соединения;
- UTF-8 в Windows-консоли;
- корректная остановка по `Ctrl+C`;
- логирование в `logs/bot.log`;
- профили зрителей в `data/viewers.dat`, стартовый баланс 100 🍊;
- ежедневная награда 75 🍊 (раз в 24 часа), ставки в монетке и слотах, дуэли, рейтинг и статистика;
- случайные дропы апельсинов (`!забрать`) и звания по балансу (`!звание`);
- музыкальные заявки с YouTube, очередь, скачивание и конвертация через `yt-dlp` + FFmpeg;
- воспроизведение и автоматическое переключение песен через OBS WebSocket v5;
- кеш MP3 с кириллическими названиями и уникальным YouTube ID;
- компактный текстовый оверлей «сейчас играет» для OBS.

## Как работает бот

```text
Twitch OAuth
    |
    +--> Helix API ------------------> состояние стрима
    |                                     |
    |                                     +--> старт стрима --> Telegram
    |
    +--> EventSub WebSocket ----------> сообщения Twitch-чата
                                          |
                                          +--> парсер команд
                                                  |
                                                  +--> проверка кулдауна
                                                          |
                                                          +--> ответ через Helix Chat API
```

В обычном режиме EventSub постоянно принимает сообщения чата, а основной цикл параллельно выполняет периодические задачи, включая проверку состояния трансляции и OAuth-сессии.

## Команды Twitch-чата

| Команда | Алиасы | Назначение |
| --- | --- | --- |
| `!команды` | `!help`, `!commands` | Справка |
| `!тг` | `!tg` | Ссылка на Telegram |
| `!дс` | `!дискорд`, `!ds` | Ссылка на Discord |
| `!баланс` | `!апельсины`, `!balance` | Баланс 🍊 |
| `!ежедневка` | `!daily` | 75 🍊 раз в 24 часа |
| `!монетка <ставка>` | `!монета`, `!coin` | Ставка с шансом 50/50 |
| `!слот <ставка>` | `!slot` | Игровой автомат |
| `!дуэль @ник <ставка>` | — | Вызов другого зрителя |
| `!принять` / `!отказ` | — | Ответ на дуэль |
| `!топ` | `!top` | Пятёрка лидеров |
| `!я` | `!профиль`, `!profile` | Статистика и звание |
| `!звание` | `!rank` | Текущий ранг и следующий порог |
| `!забрать` | `!claim` | Забрать активный случайный дроп |
| `!кости` | `!кубик`, `!dice` | Бросок кубика |
| `!шар <вопрос>` | `!ball`, `!8ball` | Magic 8 Ball |
| `!звуки` | `!sounds` | Список настроенных звуков и их цен |
| `!брух` и другие из `[sounds]` | — | Воспроизведение медиаисточника OBS за апельсины |
| `!заказать <ссылка>` | — | Добавить YouTube-видео (до 10 минут) в музыкальную очередь |
| `!трек` | — | Показать текущую композицию и заказчика |
| `!очередь` | — | Показать ожидающие заявки |
| `!скип` | `!skip` | Остановить текущую песню и перейти к следующей (только владелец канала) |

Информационные команды обычно имеют кулдаун 10 секунд, игровые — 5 секунд; `!забрать` не имеет отдельного кулдауна. Дропы запланированы раз в 10–20 минут и действуют 60 секунд. Фактическое время появления зависит от работы основного цикла EventSub. Изменение баланса и статистики сохраняется локально; дуэльные вызовы и кулдауны после перезапуска сбрасываются.

Префикс команд задаётся в `config.ini`. По умолчанию используется `!`.

Кулдауны работают отдельно для каждого Twitch User ID и для каждой команды. Например, использование `!слот` одним зрителем не блокирует `!слот` для другого зрителя и не мешает этому же зрителю использовать `!кости`. Повторная команда во время кулдауна молча игнорируется. Состояние кулдаунов хранится только во время работы программы и сбрасывается после перезапуска.

## Быстрый запуск

1. Скопируйте `config.example.ini` в `config.ini`.
2. Укажите Twitch `client_id` и `broadcaster_login`.
3. При необходимости настройте Telegram и Discord.
4. Выполните qmake и соберите проект.
5. Запустите `twitchbot.exe` без тестовых аргументов.

OAuth-токены вручную указывать не нужно. При первом запуске бот использует Device Code Flow, после чего сохраняет токены локально в `data/twitch_tokens.dat`.

## Отдельный Twitch-аккаунт бота (проверено)

Бот может отправлять сообщения **от собственного Twitch-аккаунта**, а не от имени стримера. Рабочая конфигурация проекта:

- **Канал трансляции:** `aleg_opelsin1` (параметр `broadcaster_login`).
- **Аккаунт для ответов:** `apelsinbot` (автоматически определяется из OAuth-токена).
- **Права:** `apelsinbot` назначен модератором канала `aleg_opelsin1`.

В `config.ini` оставьте `broadcaster_login=aleg_opelsin1`. Поля `bot_login` и `bot_user_id` **не нужно заполнять вручную**: бот получает их из Twitch при проверке OAuth-токена. Команды и музыка остаются привязаны к каналу стримера; сообщения в чат идут от авторизованного бота. Право на `!скип` / `!skip` определяется Twitch ID владельца канала, а не аккаунтом, отправляющим ответы.

### Первичная авторизация или смена аккаунта

1. Полностью остановите `twitchbot.exe`.
2. Если `data/twitch_tokens.dat` уже существует и содержит прежнюю авторизацию, **сначала сохраните резервную копию** в той же папке. Например, в PowerShell из рабочего каталога бота:

   ```powershell
   Rename-Item ".\data\twitch_tokens.dat" "twitch_tokens_main_backup.dat"
   ```

   Если файл с таким именем уже существует, выберите другое имя для новой резервной копии и не перезаписывайте старую.
3. Запустите бота без тестовых параметров. При отсутствии `twitch_tokens.dat` он покажет код Device Code OAuth и ссылку для активации.
4. Откройте ссылку и **авторизуйтесь именно в отдельном Twitch-аккаунте бота**. При необходимости используйте отдельный профиль браузера, чтобы не подтвердить вход от имени стримера.
5. Проверьте строки журнала: `Authorized Twitch account: apelsinbot` и `Twitch chat bot account: apelsinbot`. Бот сохранит новые токены в `data/twitch_tokens.dat` средствами Windows DPAPI.
6. Проверьте в чате канала `aleg_opelsin1` команды `!трек`, `!заказать` и `!скип`: ответы должны публиковаться от `apelsinbot`, а воспроизведение и OBS — работать как прежде.

**Важно:** пароль и email Twitch-аккаунта в `config.ini` и GitHub не нужны. OAuth-токены и резервные копии нельзя публиковать; они хранятся только локально. Для возврата к старому аккаунту сначала остановите бота, сохраните текущий файл токенов под другим именем, затем верните прежнюю резервную копию к имени `data/twitch_tokens.dat` (под тем же пользователем Windows, поскольку применяется DPAPI).

## Конфигурация

Основные параметры:

```ini
[twitch]
client_id=
client_secret=
access_token=
refresh_token=
broadcaster_login=
broadcaster_id=
bot_login=
bot_user_id=

[telegram]
bot_token=
chat_id=
channel_url=https://t.me/your_channel

[discord]
invite_url=https://discord.gg/your_invite

[bot]
command_prefix=!
```

`access_token`, `refresh_token`, `broadcaster_id`, `bot_login` и `bot_user_id` обычно не требуется заполнять вручную.

`channel_url` используется командой `!тг`, а `invite_url` — командой `!дс`. Это публичные ссылки. `chat_id` используется отдельно Telegram Bot API для отправки уведомлений.

## Сборка

Проект рассчитан на Windows и проверялся с **Qt 5.12.12 + MinGW 7.3**.

В Qt Creator:

```text
Run qmake
Clean Project
Rebuild Project
Run
```

Проект использует WinHTTP и Windows Cryptography API:

- `winhttp` — HTTP-запросы и EventSub WebSocket;
- `crypt32` — защита OAuth-токенов через DPAPI.

Старые заголовки MinGW 7.3 не содержат современных объявлений WinHTTP WebSocket API, поэтому необходимые WebSocket-функции загружаются из системной `winhttp.dll` во время выполнения.

## Тестовые режимы

```text
--test-stream
--dry-run
--test-chat
--test-twitch-chat
--test-eventsub-chat
--test-twitch-command
--help
```

`--test-chat` позволяет локально проверить разбор команд и ответы без подключения к Twitch.

`--test-twitch-command` — диагностический режим: подключается к настоящему Twitch-чату, ждёт одну команду, отвечает на неё и завершает работу.

Для обычной постоянной работы тестовые аргументы не нужны.

Основные модули:

- `obs_websocket` — запуск, остановка и контроль состояния медиаисточников OBS.

## Безопасность

`config.ini`, `data/`, `logs/` и файлы сборки исключены через `.gitignore`.

Не публикуйте:

- Twitch OAuth-токены;
- Twitch Client Secret;
- Telegram bot token;
- `data/twitch_tokens.dat`.

`config.example.ini` предназначен только для примера и не должен содержать реальные секреты. Публичные ссылки Telegram/Discord не являются токенами доступа, но в примере рекомендуется использовать шаблонные значения.

## OBS Studio — звуковые эффекты (0.8.0)

Бот подключается к OBS WebSocket v5 на `127.0.0.1:4455` и запускает медиаисточники по командам Twitch-чата. Пароль OBS хранится только в локальном `config.ini`, который исключён из Git.

Пример настройки:

```ini
[obs]
enabled=true
password=ВАШ_ЛОКАЛЬНЫЙ_ПАРОЛЬ

[sounds]
брух=Bot_Bruh,15,25
смех=Bot_Laugh,30,40
бонк=Bot_Bonk,20,30
фейл=Bot_Wasted,30,50
драм=Bot_Dramatic,20,35
```

Формат: `команда=имя_медиаисточника_OBS,общий_кулдаун_сек,цена_в_апельсинах`. Названия источников должны точно совпадать с названиями в OBS. Максимум 16 звуковых команд. Цена 0 означает бесплатный эффект.

При успешном запуске OBS-источника бот списывает цену из баланса зрителя и сохраняет профиль. При недостатке средств сообщает об этом в чат. Повторный вызов в течение кулдауна не запускает эффект и не списывает апельсины; уведомление об оставшемся времени ограничено одним сообщением в 10 секунд на эффект. `!звуки` выводит каталог с актуальными ценами.

Для диагностики подключения к OBS доступен режим `--test-obs`. В OBS следует включить WebSocket-сервер, настроить аудиовыход медиаисточников и отключить зацикливание.

## Музыкальные заявки и интеграция с OBS (0.9, в разработке)

Для музыки требуются **OBS Studio с включённым WebSocket v5**, доступные в `PATH` программы **`yt-dlp.exe`** и **FFmpeg**. На компьютере должен работать доступ к YouTube. Некоторые видео могут требовать авторизации в YouTube и не скачиваться без дополнительных настроек `yt-dlp`.

1. В OBS включите WebSocket-сервер (обычно `127.0.0.1:4455`) и укажите пароль в локальном `config.ini`:
   ```ini
   [obs]
   enabled=true
   password=ВАШ_ПАРОЛЬ_OBS
   ```
2. Создайте в OBS **медиаисточник** с точным именем `Bot_Music`. Отключите повтор воспроизведения. Бот управляет файлом и воспроизведением через OBS WebSocket.
3. Запустите бота, отправьте в Twitch-чат команду `!заказать https://www.youtube.com/watch?v=VIDEO_ID`. Бот получает метаданные, проверяет длительность (максимум 600 секунд) и добавляет заявку в очередь (до 32 ожидающих заявок).
4. Когда доходит очередь, фоновый поток загружает аудио через `yt-dlp`, конвертирует в MP3 и передаёт абсолютный UTF-8-путь медиаисточнику `Bot_Music`. После завершения песни бот переключается на следующую. `!скип` / `!skip` доступен только владельцу Twitch-канала.
5. Скачанные файлы хранятся в `music_cache/` с читаемыми названиями на кириллице и суффиксом `[YouTube_ID]`. При повторном заказе бот ищет уже сохранённый MP3 по ID и повторно использует его. Кеширование не отменяет запрос метаданных при оформлении новой заявки.

### Минималистичный текстовый виджет «сейчас играет»

Бот формирует **два UTF-8-файла с BOM** в текущем рабочем каталоге (обычно рядом с запущенным `twitchbot.exe`):

| Файл | Содержимое |
| --- | --- |
| `obs_now_playing.txt` | Название текущей песни, например `Макс Корж - Малиновый закат` |
| `obs_now_playing_requester.txt` | `Заказал: aleg_opelsin1` |

Настройка в OBS:

1. Добавьте источник **Текст (GDI+)** → **Читать из файла** → выберите `obs_now_playing.txt`.
2. Добавьте второй источник **Текст (GDI+)** из `obs_now_playing_requester.txt`.
3. Рекомендуемое оформление: белое название песни, оранжевое имя заказчика, курсив и выравнивание по правому краю. Размер и положение задаются в OBS.
4. При запуске бота, завершении трека или успешном пропуске оба файла очищаются; при начале следующей композиции обновляются автоматически.

**Очистка названий:** только для текста в OBS бот удаляет известные *концевые* приписки, например `(official video)`, `(official audio)`, `[lyrics]` и `[YouTube_ID]`. Названия MP3 и исходные записи очереди не изменяются.

Если OBS запускает последний MP3 самостоятельно, проверьте свойства медиаисточника: отключите «Повтор» и автоматический перезапуск при активации; при необходимости дополнительно управляйте его видимостью в сцене.

Для локальной разработки после обновления ветки:

```powershell
git pull origin main
```

Затем в Qt Creator выполните **Run qmake → Rebuild Project**.
